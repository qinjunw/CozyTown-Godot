# 产品目标与验收基线

日期：2026-09-19。来源为用户确认的 Godot 独立重构要求，以及 CozyTown 的可玩小镇和四人 Agent 实验平台目标。本文件记录目标，不声明实现已经完成。

## 已确认的边界

| 项目 | 约定 |
| --- | --- |
| 产品 | 独立 Godot Demo；保留小镇生活循环和四人 Agent 实验目标 |
| 平台 | Windows/PC 优先 |
| 技术方向 | Godot .NET + 独立 C# 核心；可参考、复制或重写原逻辑和测试 |
| 存档 | 首版使用自己的新档；不要求兼容 Unity 旧档 |
| 参考关系 | Unity 项目继续独立开发；不自动同步，不成为构建或运行依赖 |
| 美术 | 可沿用现有资源或重构，以最终画面和交互验收为准 |

“保持目标”约束最终可观察能力，不要求复制 Unity 的类型、场景层级、物理 API、存档布局、固定人物数量校验或编辑器生成器。具体实现通过新仓库的决策与验收形成。

## 可玩小镇

| 目标 | 首版验收方向 |
| --- | --- |
| 移动与交互 | 玩家可在小镇移动，障碍有效；附近目标、交互面板和输入门控一致 |
| 生产与经济闭环 | 购买生产资料，种植/养鸡/钓鱼，收获或领取产物，烹饪或出售，再投入下一轮生产 |
| 状态可读 | 钱包、时间、背包、快捷栏和生产条件可见；失败有可理解的原因 |
| 世界时间 | 连续推进、跨午夜、晨间结算、按小时睡眠；暂停、快进和读取后状态一致 |
| 居民生活 | 四名居民可区分，拥有个人日程，移动、到场、在家及临时活动可观察 |
| 持久化 | 保存后可继续已实现的世界与居民行为，失败不静默破坏原状态 |

当前参考行为包括每日 05:00 晨间结算、睡眠 1～12 小时、菜单/失焦暂停、五格快捷栏和角色/商店独立资源归属。它们是重构设计输入；如有意修改，应在对应决策票据说明变化及验收，不把偶然的引擎行为当作产品要求。

## 四人 Agent 实验平台

| 目标 | 首版验收方向 |
| --- | --- |
| 自主活动 | 四人在同一世界获得合法行动机会，区分其身份、状态与经历；不以两人重复运行替代四人共同负载 |
| 社交与协作 | 邀请、回应、赴约、到场、交谈、资源交付及终止具有可观察结果；真实模型允许合法拒绝 |
| 有界运行 | 限制调用预算、并发和等待；超时、迟到、取消及重复请求不产生旧状态写入或重复资源转移 |
| 事实边界 | 模型接收经过筛选的观察和经历；台词不直接创建物品、资金或已经发生的事件 |
| 连续性 | 快照覆盖已实现且影响后续行为的状态；恢复不会泄漏未来经历，也不会退还真实调用消耗 |
| 可观测 | 关联触发、观察时间、请求、候选、宿主判定、执行结果、承诺、经历及调用用量 |
| 可重复实验 | 区分固定替身、记录回放和真实模型运行；冻结初态与配置，保留失败/中断，回放分歧可定位并停止 |
| 可交付 | 从干净检出构建并运行 Windows Demo，能按说明完成玩法、实验、保存读取及记录导出 |

完整快照和 Agent 调度在参考项目中已有实现可研究；四人实验入口、轨迹导出和分歧停止回放仍是本重构必须交付的目标，不能把参考项目的计划当作已完成证明。

## 本轮边界之外

多人联网、千人社会模拟、新地图体系、额外职业生产闭环、复杂需求与长期关系系统、强制网页/移动端支持，以及 Unity 旧档迁移。它们不因重构自动成为首版验收条件。

## 完成条件

新仓库的同一候选提交应贯通可玩闭环、四人实验、完整保存恢复、观察与记录导出、固定输入回放和 Windows 独立运行。确定性约束通过测试，画面与交互有实际运行证据；真实模型行为单独报告样本、费用和局限，不用测试绿色代替模型可靠率。
