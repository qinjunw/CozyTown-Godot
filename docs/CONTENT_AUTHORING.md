# 内容来源与一致性合同

2026-09-20 用户确认采用分工编辑：Godot 场景维护空间布局，独立 JSON 维护居民、日程和资源定义，两者通过稳定身份关联。决定见[确定地图、居民与感知共用的内容数据来源](https://github.com/qinjunw/CozyTown-Godot/issues/5)。本文件记录内容合同；提取器、联合校验与小镇实现见[切片操作与维护](PLAYABLE_SLICE.md)，执行结果见[切片验证记录](verification/four-resident-slice.md)。

## 证据与选项

当前内容提取与联合校验入口为本仓库的 [TownContentLoader.Load](../game/Host/TownContentLoader.cs) 和 [TownContent.Create](../src/CozyTown.Core/Town/TownContent.cs)。

历史设计参考为 Unity `68a1dde7c7099f3e9ee7e975141d0bf9d18099aa` 的 [TownLocalObservation2D.TryConfigureDevelopmentMap](https://github.com/qinjunw/CozyTown/blob/68a1dde7c7099f3e9ee7e975141d0bf9d18099aa/Assets/CozyTown/Unity/Npc/TownLocalObservation2D.cs)，链接需要 CozyTown 私有参考仓库访问权限。该实现使用住宅数、地点坐标、节点路径识别开发地图；部分位置或层级改变会使观察登记失效。重构保留局部观察行为目标，重新定义登记方式。

Godot 的场景与 Resource 都支持文本序列化，C# 导出属性可在 Inspector 编辑；因此 AI 改文件与可视化编辑并不互斥。Resource 导出的 Node 属性不能作为跨内容引用方案，官方诊断 GD0107 要求这类属性处于 Node 派生类中。业务引用应使用明确身份，由宿主解析。[TSCN 格式](https://docs.godotengine.org/en/4.7/engine_details/file_formats/tscn.html)、[Resources](https://docs.godotengine.org/en/4.7/tutorials/scripting/resources.html)、[C# 导出属性](https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/c_sharp_exports.html)、[GD0107](https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/diagnostics/GD0107.html)。

| 编辑方式 | 可视化操作 | AI / 代码编辑 | 维护代价 |
| --- | --- | --- | --- |
| 场景与文本分工（已选） | 在 Godot 摆放地图和空间标记 | 编辑文本场景或居民、日程及资源配置 | 两种输入需要联合校验，每个字段仅有一个作者来源 |
| 文本作为全部来源 | 地图预览由数据生成；可视化修改需要回写工具 | 所有内容直接改文本 | 需要地图生成或回写工具，不能直接保存预览作为另一份权威地图 |
| 场景与 Resource 作为全部来源 | 地图与内容均在 Godot 编辑 | 可编辑文本资源，需由 Godot 验证 | 独立核心实验须先提取内容，内容制作依赖 Godot 导入 |

## 数据所有权

| 内容 | 唯一作者来源 | 派生或运行时数据 |
| --- | --- | --- |
| 地图、地点、住宅入口、交互锚点的位置 | Godot 场景中的空间标记 | 地图坐标、目标位置与可观察对象索引 |
| 道路节点、连接与空间几何 | Godot 场景 | 可行走连接与空间查询输入；连接引用地点身份 |
| 障碍、观察区域、空间归属 | Godot 场景中的对应形状与标记 | 碰撞查询与局部观察使用的几何事实 |
| 居民清单、住宅/出生地点引用、个体定义 | 独立 JSON 内容 | 按清单创建四名居民及身体绑定；场景不再手写另一份居民名单 |
| 世界日程、资源与初态账本、规则参数 | 独立 JSON 内容 | 核心初始化状态；运行后资产、位置、活动由核心维护 |
| 可复用交互定义与观察公开属性 | 独立 JSON 内容 | 场景实例通过固定身份/定义引用绑定能力 |
| 图像、动画、声音及表现资源 | Godot 资源及场景 | 展示；不创建活动结果或资源 |

“共用来源”意味着导航、交互与感知取得同一版本的地点身份和几何；不要求图像、碰撞形状和可见范围共用一个形状。住宅的门口与室内入口可以是两个明确命名的地点，不能让三个系统各自维护同一门口的坐标。

在 Godot 中移动商店时，将店体、碰撞、入口和所属区域放在同一可移动父节点下，保留它们的业务身份。日程继续引用原入口身份；需要调整道路接入时，在场景中修改道路连接，不到人物代码或观察白名单补坐标。修改居民日程或资源初态只编辑对应 JSON。两类修改都通过同一个内容校验流程后，再启动新运行。

## 身份与运行状态

稳定身份显式保存在作者数据中，作为跨场景、日程、观察和存档的引用。显示名、节点名、节点路径、资源路径、Godot 运行实例编号与数组次序都不作为身份。移动地点、改显示名或整理节点层级不改身份；复制为另一个地点必须赋予新身份，验证器不能自动随机修复。

地点及地图放置对象的实例身份写在场景标记，居民身份写在居民清单，其他字段只引用。可复用业务定义身份写在 JSON 定义表，与使用它的世界实例身份分开。

区分共享模板与放置实例，也区分经济主体与空间锚点。例如商店主体 `shop.general` 与入口地点 `place.shop.general.entrance` 分别有身份，日程引用入口，库存属于商店主体。移动入口不创建新库存；同一房屋模板的两处实例必须具有不同地点身份。示例名称只说明关系，不作为已存在的地图清单。

场景引用的碰撞形状、区域形状等几何 Resource 属于场景作者输入，连同表现资源纳入输入依赖摘要。可复用的几何与表现 Resource 可以共享，放置实例的身份仍逐一登记。交互能力、观察公开属性等业务字段只引用 JSON 定义，不在 Resource 再写一份。每个居民的资产、观察、经历、活动和模型待办分别维护。地图内的公共可观察对象目录不等于居民已知信息。一次局部观察仍由该居民当前已提交位置、空间、范围和可公开属性筛选。

初态字段只用于新运行。静态地图与定义参与初始化及恢复兼容检查；加载快照时，不用初态钱包、出生点或默认日程进度覆盖已恢复状态。内容修改后的存档兼容与恢复策略由[确定新存档、状态续接与实验回放的合同](https://github.com/qinjunw/CozyTown-Godot/issues/6)确定。

## 提取、校验与派生数据

编辑验证、构建与启动共用内容提取和联合校验逻辑。Godot 解析场景和资源，将有效几何与 JSON 定义合并为不含引擎对象的只读内容清单。独立核心消费普通数据；不能用 NodePath 或 Godot 对象代替已解析身份。验证模式只加载内容，不推进世界或请求模型。

Godot 提供 headless 启动、PackedScene 实例化及 Node2D 组合变换 API，支持通过项目的 C# 宿主实现这一提取入口；这些 API 并不自带本项目的联合校验器。[命令行](https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html)、[PackedScene](https://docs.godotengine.org/en/4.7/classes/class_packedscene.html)、[Node2D](https://docs.godotengine.org/en/4.7/classes/class_node2d.html)。

提取器统一处理节点层级变换、地图坐标、道路端点与区域形状。遇到尚不支持的缩放、旋转或形状，应指出文件、标记和字段并失败，不能默默省略或改用旧坐标。单位、量化及容差随实际地图切片验证固定。

清单附格式版本、规范化内容指纹、输入依赖摘要与提取器版本。相同语义输入按稳定身份排序后应得到相同内容指纹；生成时间戳与节点遍历顺序不改变它。派生清单不能手改；源文件改变后重新生成。干净构建从作者源生成，启动验证与打包内容匹配；验证失败不得回退到残留的上次成功输出。生成位置、导出包含规则与可执行命令在实现时加入构建脚本，导出包必须携带所需内容及验证信息。

内容指纹与存档结构版本分别记录。地图锚点或碰撞变化，即使保留相同身份，也可能使旧路线失效。存档票据据此确定兼容性与加载失败行为；不因身份仍存在就承诺旧档可继续。纯贴图变动与影响规则的几何/属性分别记录，避免把素材文件重命名等同于居民身份变化。

JSON 定义与场景引用必须联合校验：身份唯一、引用存在且类型匹配、居民身体绑定一对一、初态资源有效、时间窗口可解析且无不允许的重叠、必需日程地点可达、形状有效且数值有限。四名指定居民是当前内容包的切片验收条件，不写成通用加载器只允许四人的限制。配置错误在进入运行之前中止，列出来源和错误；初态不得含指派社交配对与接受结果的演示脚本。

静态连通检查不能证明实际身体能通过道路；实际碰撞、可达性和观察结果仍须在 Godot 切片验收。

当前 `production` 校验覆盖母鸡、钓点、厨房与配方身份、地点和资源引用、正整数材料及产量、无重叠的鱼类抽值区间、非零随机种子，以及有厨房时必须有配方。入口位置由共享地图校验；实际身体沿路线到达与交互由 Godot 场景验收覆盖。生产目标身份与地点身份分开；母鸡状态表现不另建碰撞身体。新增鸡舍、池塘与厨房共用场景提取的地点和运动几何，见[生产内容与空间](PLAYER_PRODUCTION.md#内容与共享空间)。

首切片按“编辑后重启/重新构建”应用内容修改，运行中的核心状态不因修改 JSON 或 Resource 被后台覆盖。运行时热重载与修改世界编辑器不加入本票范围。

## 一致性验收

| 输入或操作 | 可观察判据 |
| --- | --- |
| 移动商店及其所属锚点 | 重新生成后，碰撞、日程目标、交互位置和观察对象使用同一版本几何；没有第二份手改坐标，商店库存身份不变 |
| 重命名节点或改变父层级，保持最终变换 | 业务身份与关联保持，变换提取结果相同 |
| 复制住宅但保留身份 | 启动/构建失败，定位两个冲突来源；赋予新身份并补引用后通过 |
| 删除被日程引用的地点 | 指出居民、日程字段和缺失地点；不默认选择附近地点 |
| 修改居民日程或初始资源 | 新运行采用新值，模型观察仍按该居民实际状态过滤；存档恢复按其合同处理 |
| 只改作者源，保留旧派生文件 | 从源重新生成或明确失败；不能运行过期清单 |
| 重复生成相同内容，改变节点遍历顺序 | 按身份排序的语义数据和内容指纹相同；居民候选顺序不依赖节点遍历顺序 |
| 父节点位移/旋转/缩放，或出现不支持形状 | 支持的变换得到一致几何；不支持项明确失败 |
| 编辑一次住宅门口或观察范围 | 导航目标、交互资格和局部观察各自按同一内容版本工作；实测边界点与室内外分隔 |
| 共享人物表现资源并修改一个人的运行资产 | 只有对应居民状态变化，其他居民不受影响 |
| 干净检出并导出 Windows | 无旧缓存也能生成内容；导出包使用同一内容指纹与名单 |

本票只决定编辑合同和验收。内容提取器、校验器、地图与居民实现，以及上述场景用例的运行证据，由[用垂直切片验证 Godot 场景、像素交互与调试体验](https://github.com/qinjunw/CozyTown-Godot/issues/7)交付，依照[首切片范围与验收](FIRST_PLAYABLE_SLICE.md)检查。存档/回放票据消费稳定身份与内容版本，决定不匹配时的行为。
