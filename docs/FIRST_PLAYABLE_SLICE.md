# 首个可玩切片：四人自主互动

本文件定义待实现的首切片范围与验收，不声明这些功能已经完成。范围决定见[确定首个可玩切片的范围与公开验收](https://github.com/qinjunw/CozyTown-Godot/issues/4)，完整 Demo 目标见[产品基线](PRODUCT_BASELINE.md)。

## 已确认的交付方向

首切片交付一个 Windows 可运行的小镇场景，展示 Mina、Eli、Ren、Sora 在世界安排的日程中，依据各自状态和局部观察自主互动。玩家可移动、观察和交谈；画面达到可对外演示的完成度。第一切片同时包含独立规则与真实模型，玩家种植生产循环在后续切片交付。

世界日程优先。居民在空闲窗口内决定是否接近、邀请、回应或交换资源，世界日程不预写社交对象及结果。不同居民可以共用决策实现或模型服务，但其身份、状态、观察和决定必须分别维护。

验收初态可以固定资源、人物状态和随机种子，便于复查。场景或测试驱动不能在运行中替居民逐步指定配对、接受和交付，再将这条编排路径当作产品的自主行为。

## 规则、模型与世界的分工

下表将已确认的“独立规则＋真实模型”落实为验收边界；请求、预算与失败处理见[真实模型接入合同](REAL_MODEL_CONTRACT.md)。

| 部分 | 职责与可观察结果 |
| --- | --- |
| 每名居民的规则 | 根据自身状态、日程和局部观察形成行动机会、筛选候选；保留选择对象、拒绝和不行动的空间；没有可用模型响应时给出合法回退 |
| 每名居民的模型决定 | 使用该居民可知的信息，参与互动对象、提议或回应等实际选择，并可生成对话；记录模型候选与简要依据，不能仅给预写剧情润色台词 |
| 世界规则 | 校验日程窗口、当前身份与请求有效性、到场及资源条件，提交合法行动与资产变化；对非法、过期和重复候选给出拒绝原因 |
| 场景与界面 | 展示已发生的移动、活动及结果；动画完成或台词不能自行创建到场、资产或已发生事件 |

正常日程可执行时，冲突的互动应被拒绝或结束，居民转入下一项日程。世界要处理行程和活动的终止原因，不能通过瞬移、丢弃承诺或重播交付掩盖冲突。日程边界后的迟到响应不能重启已失效的互动。

## 首切片范围

| 范围 | 必须提供的能力 |
| --- | --- |
| 小镇与玩家 | 一张可对外演示的精修小场景；玩家移动、障碍、交互提示、居民交谈；可辨认的生活地点与路线 |
| 四人自主生活 | 四人同处一个持续运行的世界，各自获得合法决策机会；按日程移动、到场和活动；社交对象及回应由各自决策产生 |
| 社交与资源 | 邀请、回应、赴约、交谈、结束，以及受规则保护的资源交付；初始资源来自明确的初态账本，不依赖尚未实现的玩家生产链 |
| 时间与暂停 | 连续推进及跨日的居民日程；菜单和失焦暂停；暂停期间停止世界推进和行动提交，恢复后重新检查待处理结果 |
| 保存恢复 | 覆盖已实现的世界及居民状态，至少验证赴约途中、等待回应或交谈中的续接；已发生的调用消耗不因读档回退 |
| 观察与记录 | 可查看四人的当前活动、相关观察、承诺、候选来源、世界判定及结果，并导出本次运行记录；开发者全局视图与居民局部观察分开 |
| 真实模型路径 | 实际服务接入、有限调用与等待、明确的故障及规则回退；同时保留无需真实调用的自动测试入口 |

首切片的演示方式需让用户能独立完成进入场景、移动、观察、交谈、暂停、保存读取及退出。开发者详情可以放在观察入口；正常游戏界面应呈现人物与活动反馈，而不是工具链诊断窗口。

## 公开验收步骤与证据

这里的公开验收是仓库内明确、可复查的步骤；仓库仍为私人仓库。实现者须为同一候选提交提供可运行包、操作说明、固定初态及完整运行记录。

| 检查 | 操作与通过判据 | 证据 |
| --- | --- | --- |
| 场景与操作 | 从 Windows 导出包启动，玩家实际移动、碰撞、选中交互对象并交谈；镜头、遮挡、动画和界面反馈可读，1280×720 与 1920×1080 窗口下无裁切或重叠 | 实际键鼠操作与运行录像/截图；不能只用内部信号或核心测试代替 |
| 四人分别决策 | 在同一世界中为四人提供可行动的情境；分别查看各自观察、规则筛选、模型候选及执行/拒绝结果 | 带居民 ID、观察时刻和决定来源的运行记录；不是两人实验重复两次 |
| 自主互动对照 | 基准初态具有社交机会；另设改变资源分布、可见对象或空闲窗口的对照初态。规则重新评估，居民能另选合法对象、修改提议、拒绝或不互动 | 初态差异与全部样本；真实模型不要求每次出现指定配对，也不要求任意数据变化必然改变结果 |
| 日程优先 | 分别观察空闲时发起互动、繁忙时拒绝，以及互动遇到下一项日程边界；注入旧互动的迟到响应 | 活动结束/拒绝原因、日程推进和响应拒绝记录；没有失效互动重新占用日程 |
| 资源一致性 | 在合法双方到场后完成一次交付，再检查未到场、资源不足及重复提交的情况 | 普通交易前后双方总资产守恒；失败不部分扣款、扣料或产出，重复结果不再次交付 |
| 状态续接 | 在赴约途中及等待回应或交谈时保存读取，继续原行程、承诺、会话及逻辑待办；验证旧会话响应被拒绝 | 保存点与恢复后记录可关联；没有清空后重新配对、重新邀约或重播交付，调用消耗不减少 |
| 暂停与恢复 | 菜单与失焦原因同时存在时，解除其中一个仍保持暂停；暂停期间收到结果，恢复后才检查并受理有效结果 | 世界时间、行动提交和请求记录，排除暂停期间由异步回调改写世界 |
| 模型故障 | 注入超时、非法回复及预算耗尽，观察规则回退或明确失败；真实服务运行与这些故障样本分别统计 | 原始模式、响应/错误、回退来源和实际消耗；缺少凭据或只有回退成功不能判真实路径通过 |
| 画面验收 | 用同一导出包展示四人活动、玩家交互、会面与保存恢复；人物辨识、场景比例、动画衔接、遮挡和界面风格一致 | 用户对实际画面和交互的反馈；一张截图或作者自评不能关闭视觉验收 |

成功交付及失败不写入的规则可用固定输入测试验证；自主性验收还必须使用正常的居民决策入口。测试脚本直接发送候选只能证明规则执行，不能证明居民自行作出了决定。

真实模型运行保留全部样本、拒绝、失败和中断。四人都要有实际模型决定的证据；接口可达或一名居民的一次调用不足以证明四人路径。模型可以合法拒绝，不能为了演示成功让规则偷偷替它接受，再把结果计入真实模型成功。

## 后续交付与合同衔接

下表属于完整 Demo 的后续工作，不因首切片聚焦居民而从目标中删除。

| 工作 | 首切片与后续的边界 |
| --- | --- |
| 玩家生产与经济循环 | 种植、养鸡、钓鱼、烹饪、商店再投入及相应业务界面在后续切片贯通；首切片保留居民资源交付的不变量 |
| 按小时睡眠与生产结算 | 随玩家生活循环交付；首切片须先验证连续时间、跨日日程及暂停恢复，不能用跳时替代身体到场 |
| 完整记录回放 | 首切片提供运行记录导出；可重建输入与模型响应、定位并停止分歧的完整回放在后续交付。字段与身份合同必须在首切片实现前由存档/回放票据确定，避免只留下不可复用的自由文本日志 |
| 跨日真实模型评测 | 首切片证明有限预算内的实际接入、行为及故障边界；长时可靠率、场景规模和指标阈值仍需专门评测 |

内容编辑方式已确定为 Godot 场景维护空间布局、独立 JSON 维护居民与日程等定义；共用身份、派生数据和场景修改验收见[内容来源与一致性合同](CONTENT_AUTHORING.md)。相应提取、校验与场景实现仍由垂直切片交付。

[存档与回放合同](SAVE_REPLAY_CONTRACT.md)已确定完整状态、恢复发布边界、在途请求、内容兼容与记录输入。首切片实现其中的保存恢复、跨读档预算保护和结构化记录导出；完整回放执行器仍在后续交付。

[真实模型接入合同](REAL_MODEL_CONTRACT.md)已确定 DeepSeek 与独立 C# 接入、人民币 5 元和 48 次发送的共用预算、并发与超时，以及真实样本和故障的统计边界。接口探针与两组四人场景分别使用 4、22、22 次阶段上限，失败和恢复补发均计入；接口探针不能替代场景验收。

具体美术方案和可运行结果由[垂直切片票据](https://github.com/qinjunw/CozyTown-Godot/issues/7)展示并取得用户反馈；完整 Demo 的后续实施顺序由[候选版本验收票据](https://github.com/qinjunw/CozyTown-Godot/issues/8)衔接。
