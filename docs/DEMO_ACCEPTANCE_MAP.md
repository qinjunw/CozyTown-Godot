## 每张功能票的完成边界

每次引入影响后续行为的状态，都随功能交付以下证据：

1. **原子行为**：经济主体归属、操作身份、成功/拒绝及合法创建/消耗可核对。普通交易仍守恒，生产和按日替换库存不能靠删除资产校验接入。
2. **完整续接**：钱包、库存、生产/领取状态、结算游标、随机状态、待办和已接受时间推进量进入同一快照边界；必要字段、引用及模拟指纹验证同步更新。不兼容拒读，保护当前世界。
3. **可复现输入**：记录请求及拒绝、顺序、计时、随机/空间事实与完整检查点，不能仅记录成功产物。回放执行器先后合入不改变责任：先合功能提供输入及样例，后合入的一方负责适配并补跑已合入功能的对应样例。
4. **可见操作**：从正常 Windows 入口完成成功与失败流程，展示余额、时间、条件、等待和错误；新增界面延续首切片的演示标准。

回放线可与玩家资产线并行。核心回放完成后即可验证 Godot 场景，无须等待全部生产玩法；合并时以当时已实现的命令和状态为准。完整综合评测等全部功能及两类回放就绪，不接受遗漏新功能的旧样例通过。

## 候选与证据规则

| 层级 | 必须证明 | 不能据此推定 |
| --- | --- | --- |
| 核心/宿主固定测试 | 原子操作、四人公平、暂停、截止、迟到/重复、跨进程恢复竞争和文件失败符合合同 | 真实模型长期可靠率或实际画面可用 |
| 核心记录回放 | 记录输入经规则重算后，身份、资产、阶段、待办和去重状态逐边界一致 | Godot 再次计算过碰撞 |
| Godot 场景回放 | 对应引擎/场景重新计算空间，身体及规则状态在版本化容差内一致 | 缺场景依赖或引擎变更后的跨版本一致 |
| 真实运行 | 实际发送、解析、采用、执行、拒绝/等待、回退、用量和未知项均有来源 | 回退算模型成功，或两组短时样本代表长期表现 |
| Windows 人工验收 | 同一完整候选在 1280/1920 窗口的操作、布局、长按/点击移动和全部玩法可用 | 旧首切片反馈自动接受新增功能 |

综合评测先过离线门，再冻结候选并执行已批准真实样本。源提交、内容/引擎版本、初态、配置、输入、输出报告与包哈希须相互关联。修复改变候选后重核受影响项，旧真实样本保留原版本；需要新调用时仍受明确授权约束，不自动重跑。

最终交付以[产品基线完成条件](PRODUCT_BASELINE.md#完成条件)为准：同一候选贯通玩法、四人实验、保存恢复、观察导出、回放和 Windows 独立运行。关闭路线票只表明后继职责和依赖明确，完整 Demo 的验收由最终交付票承接。
