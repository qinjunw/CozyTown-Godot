# 玩家资产与商店操作

普通新档提供 300 金币、24 格空背包。橡木杂货铺的资金和库存属于 `shop.town.general`，入口引用地点 `shop`；它们与米娜的随身资产分别保存。

## 操作

| 输入 | 结果 |
| --- | --- |
| 靠近杂货铺门口按 E / 点击交互按钮 | 打开购买、出售面板；世界暂停 |
| 选择商品、调整数量、确认购买或出售 | 重新检查报价、距离、库存、资金和背包容量，显示结果 |
| B / 背包按钮 | 打开只读背包 |
| 1～5 / 点击快捷栏格子 | 选择一格，不装备或消耗物品 |
| Esc / 收起 | 关闭当前面板并解除它持有的暂停 |
| F5 / F9 | 保存或恢复双方资产、快捷栏选择与操作去重记录 |

物品按内容目录顺序排列，每堆最多 99；大于一堆时展开多个槽。快捷栏是背包前五槽的投影，物品移除后向前补位。满包按展开后的槽数判断，不按物品种类计数。背包显示不提供拖放或物品使用入口。

商店面板暂停世界时允许明确的玩家交易；菜单、失焦、读档和故障暂停会阻止交易。居民自主决定仍经过原派发门，不因商店面板打开获得暂停例外。交易资格由核心重新检查入口距离与视线，打开面板本身不授权远程交易。

## 内容与初态

[town.json](../game/Content/town.json) 定义玩家、商店初态和各方向报价。`buyPrice` 是玩家买入单价，`sellPrice` 是玩家售出单价；零表示不提供该方向。

18 项物品、报价、堆叠和容量规则参考 Unity `68a1dde7c7099f3e9ee7e975141d0bf9d18099aa` 的 [DefaultMvpContent.cs](https://github.com/qinjunw/CozyTown/blob/68a1dde7c7099f3e9ee7e975141d0bf9d18099aa/Assets/CozyTown/Runtime/Content/DefaultMvpContent.cs)，链接需要 CozyTown 私有参考仓库访问权限。第一日库存沿用固定参考的种子 12345、商店身份、第一日及补给算法 1 的结果：胡萝卜种子 4、番茄种子 3、鸡饲料 9、面粉 6；商店初始资金 10,000。当前晨间补给见[种植与睡眠](PLAYER_FARMING.md)，产物生成和领取见[养鸡、钓鱼与烹饪](PLAYER_PRODUCTION.md)。

种子、饲料、盐和面粉只能买入；作物、鸡蛋、鱼和菜肴只能出售。普通新档从空背包开始，产物经种植、养鸡、钓鱼或烹饪取得后可出售。四居民原有的浆果、麦粒、鲜鱼和热汤继续使用原社交资源身份，不自动当作新增目录中的鱼或菜肴。

物品图标来自同一固定参考的 `Items/item_mvp_16.png`，映射保存在 `game/Art/catalog.json`。来源哈希见[美术来源](art/SOURCES.md)。

### 公开交易验证初态

双向交易验收使用 `economy-fixture`，其初始背包在 `game/Content/economy-fixture.json` 明列土豆 2、鸡蛋 3、鲤鱼 1、烤土豆 1。界面显示“交易验证初态”，只接受规则模式，并有不同于普通初态的模拟指纹和存档阶段。

```powershell
& '<export-directory>/CozyTown.exe' -- --scenario=economy-fixture --data-dir='<absolute-test-directory>'
```

使用独立数据目录避免覆盖普通玩法存档。该入口仍通过正常交互、交易和存档路径，不直接改运行中的钱包或背包。

## 原子提交、记录与恢复

一次交易将两方物品和资金连同操作回执一起提交。缺钱、缺货、满包、非法数量、报价变化、不可交易方向、不可到达或溢出都返回可区分原因；拒绝不留下部分资产变化。

同一操作身份的重复投递返回原结果，不重复转移；同一身份换参数拒绝。每次有意购买使用新的操作身份。重复及拒绝也可作为新的输入记录，原资产回执保持有效。

宿主在发布经济状态之前，将版本化 `player_economy_command` 同步写入运行日志。记录包含有序输入、请求及结果、拟提交的完整经济检查点，以及内容指纹、世界序号和宿主路线/暂停上下文。记录失败时保留提交前状态并立即停止推进和派发；成功记录返回后才发布候选状态。

快照同时保存玩家与商店资产、容量、快捷栏选择和操作回执。结构版本、必要字段、内容引用、回执与资产余额需要通过预检；不以初态资产修补旧档。旧结构拒绝读取并保留当前世界。普通转移继续守恒，生产或补给另记合法创建/消耗，不能删掉资产校验。

输入与检查点可通过[离线核心回放](REPLAY.md)及 [Godot 场景回放](SCENE_REPLAY.md)核对。保存、导出成功不等于回放已经通过；回放需使用匹配版本的运行包和场景依赖。

## 验证入口

`tools/windows/verify.ps1` 执行核心/宿主测试、内容检查、四人回归及交易场景检查，再导出 Windows 包复核。加 `-Graphical` 时生成商店、背包与失败提示的场景截图。

也可对匹配版本的导出包运行：

```powershell
& '<export-directory>/CozyTown.exe' --headless -- --economy-smoke --scenario=economy-fixture --report='<absolute-report.json>' --data-dir='<absolute-test-directory>'
```

自动场景检查经真实 Godot 路线、UI 回调和合成键事件执行；真实 Windows 键鼠操作另行记录。

版本、测试结果、截图及待验事项见[玩家经济验证记录](verification/player-economy.md)。
