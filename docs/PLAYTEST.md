# Windows 试玩与人工验收

本清单用于实际打开 Windows 候选程序，检查键鼠、画面和玩法。表内结果初始均为“未测”；请按实际操作改成“通过”“失败”或“未测”。自动检查和历史候选的通过记录不能代填本候选的人工结果。

## 取得并打开候选

1. 按 [Windows 程序交付](WINDOWS_DELIVERY.md)取得交付者指定的 Windows 程序 ZIP，核对源码 SHA 和该 ZIP 的 SHA-256。文档入口不表示已经存在公开 Release 下载；没有指定候选包时，先记录“尚未取得候选”。
2. 将程序 ZIP 完整解压到一个可访问的文件夹。打开随包的 `START-HERE.md`，记录候选身份，再双击 `Start-Playtest.cmd`。保留整个解压目录。
3. 该入口使用规则模拟与固定对话客户端，不需要模型密钥。试玩数据保存在 `%LOCALAPPDATA%\CozyTown-Godot\Playtests\<sha12>`，其中 `<sha12>` 是候选源码 SHA 的前 12 位。同源码提交的候选重复启动会复用该目录；不同源码提交分别保存。重新取得同源码的程序包时，仍需记录新包摘要，并注明是否读取了此前的存档。
4. 游戏不会在重开时自动读入上次存档。按 F5 保存；退出后再次双击同一入口，再按 F9 读取。`save.json`、`runs/` 和 `exports/` 都在上述试玩数据目录内，请保留它们以便核查问题。

下列数值按普通新档编排：第 1 天 09:00、300 金币、24 格空背包。若已按 F9 读取旧进度，请在反馈里写明实际起点，按物品和金币的变化量核对，勿将不同起点混为新档结果。玩法入口详见[小镇操作](PLAYABLE_SLICE.md)。

## 阻断与可选检查

下列情况应记录为失败并停止宣布完整发布通过：候选源码或程序 ZIP 摘要不一致；无法启动或持续崩溃；保存、读取、交易、生产或导出失败；无提示丢档；拒绝操作仍扣款或扣料、重复生成产物；身体穿过建筑；关键按钮因显示问题不可操作；离线入口意外进入真实模型模式。出现错误时先保留现有文件和错误提示，再反馈；不要覆盖唯一的问题存档。

最低必测项出现失败，或仍有“未测”（包括 P07 未获鱼、P10 未覆盖全部四人），本候选的状态应记为“人工验收未完成／未通过”，并列出具体编号。额外配方、满包边界、更多分辨率与长时间运行可另记未测；不得用这些可选项目代替最低必测项。

真实模型检查另列为可选项。仅在已有有效本机配置、可用账本和明确允许的预算时，按 [Windows 真实试玩入口](REAL_PLAY_LAUNCHER.md)使用单独的真实模式入口及数据目录。不要将本清单的 `Start-Playtest.cmd` 改为真实模式，也不要重新初始化或清零既有预算。记录真实模式的来源、实际结果和失败原因；规则回退、固定示例或仅有文本显示均不能单独证明真实模型行动执行成功。
