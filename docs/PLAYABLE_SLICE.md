# 四人小镇切片操作与维护

默认入口为 `game/Town.tscn`。小镇包括四名独立居民、日程移动、邀请、回应、赴约、交谈和双方同意的资源交换。玩家可以移动、交谈、观察、暂停及存读档。真实模型运行需要显式配置；普通启动采用独立规则。

四人切片之后已加入玩家钱包、只读背包、五格快捷栏和独立商店买卖，见[玩家资产与商店操作](PLAYER_ECONOMY.md)。种植、清晨结算与按小时休息见[种植与睡眠操作](PLAYER_FARMING.md)，喂鸡领取、池边钓鱼和五份配方见[养鸡、钓鱼与烹饪](PLAYER_PRODUCTION.md)。完整记录可由[核心 CLI](REPLAY.md)及[Godot 场景入口](SCENE_REPLAY.md)回放；两天输入与预算用途见[完整 Demo 运行说明](FULL_DEMO_RUN.md)。首切片的画面与键鼠证据见[切片验证记录](verification/four-resident-slice.md)，新增功能使用各自的验证记录。

## 启动与操作

在 Windows x64 上运行 `tools/windows/verify.ps1 -Graphical` 后，打开其输出目录中的 `windows/CozyTown.exe`。保留整个 `windows` 目录，程序使用随包提供的 .NET 运行时。构建前的工具安装见 [Windows 工具链](WINDOWS_TOOLCHAIN.md)。

| 操作 | 结果 |
| --- | --- |
| WASD / 方向键 | 移动玩家，受地图碰撞限制 |
| 点击地面 | 沿可行路线行走；方向键输入可取消点击路线 |
| 靠近居民后按 E，或点交谈按钮 | 打开固定回应与可选单段生成；交谈窗口暂停世界 |
| 靠近杂货铺门口按 E | 打开商店买卖面板；入口附近优先交互商店 |
| 靠近菜地后按 E | 选择附近地块，种植、浇水或收获 |
| 靠近“我的家”门口后按 E | 选择休息 1～12 个整小时并确认 |
| 靠近鸡舍、池边或小馆入口后按 E | 喂鸡或领取、抛竿、选择厨房配方制作 |
| B / 1～5 | 只读背包 / 选择快捷栏格子 |
| 点击居民或顶部头像 | 跟随该居民并打开观察手册 |
| Tab / 观察手册 | 切换观察面板；面板是全局开发者视角，模型只接收角色自己的冻结观察 |
| 回到玩家 | 镜头回到玩家，关闭观察面板 |
| Esc / 菜单 | 暂停、继续、保存、读取、导出记录或退出 |
| F5 / F9 | 保存当前状态 / 读取最近存档 |

失焦、菜单、交谈、背包、商店、种植/睡眠和生产面板分别持有暂停原因；全部解除后世界才继续。确认睡眠仅允许该次休息推进世界，其他暂停原因仍会阻止休息。暂停期间逻辑请求的现实等待截止仍推进，已返回候选保存在邮箱中，恢复后由世界校验。存档拒绝时保持当前世界；文件发布前失败保留原主档，发布后的记录故障会单独报告并暂停。

完整模型回复已到达但尚在结算或落盘时，界面提示稍后保存，避免写入无法续接的半份回复。运行记录中断后世界暂停；可以重新读取一份合法存档形成新分支，其他暂停原因继续保留。

默认数据位于 Godot 的 `user://town`，Windows 路径通常为 `%APPDATA%/Godot/app_userdata/CozyTown/town`。`save.json` 为当前存档，`.previous` 为替换前备份，`runs/<branch-id>` 保留每次新运行或恢复的记录。观察手册可导出 ZIP，并打开导出目录。

## 真实模型运行

以下配置对应原首切片预算，其 48 次发送已经用尽。完整 Demo 的新配置、两天评测和用户试玩入口见[完整 Demo 运行说明](FULL_DEMO_RUN.md)；新实验的离线门已通过，人工验收和真实样本仍待完成。

复制 `game/Content/local-model.example.json` 到忽略的 `.local/` 目录，填入仓库外凭据文件和**现有**预算账本的绝对路径。凭据 JSON 必须有且只有一个 `Todo=CozyTown` 项及其 `testingAPIKey`。模板不能直接用于运行，程序不会创建新预算账本。

```powershell
& '<export-directory>/CozyTown.exe' -- --model-config='<absolute-local-config>'
```

普通真实模式同样受总预算、阶段上限、超时、并发和恢复补发限制。基准为默认初态；`--scenario=counterfactual` 只切换资源分布。规则启动不能静默读取真实模式存档；必须显式提供模型配置。预算、候选来源和拒绝原因可在观察手册及 JSONL 中查看。

真实实验的两组执行前条件、停止条件及样本口径见[预登记计划](verification/four-resident-run-plan.md)。`--real-experiment` 是受限实验入口，配合绝对 `--report=`、`--data-dir=` 和可选 `--screenshot=` 输出证据；不要通过重跑或新建账本刷新额度。

## 内容编辑与验证

空间来源为 `game/World/TownMap.tscn`：`role` 和 `id` 元数据登记地点、道路、障碍和观察区域。空间提取支持平移和矩形形状。住宅、商店的图像、身体碰撞和入口共用父节点；移动后需同步调整该场景中的道路接入端点。改显示名、节点名或层级不改变业务身份。

居民、日程、资源及基准初态位于 `game/Content/town.json`，对照资源位于 `counterfactual.json`。日程覆盖完整一天且不重叠。内容修改后重新构建或重启；运行中不热替换逻辑状态。

验证脚本依次执行核心、模型和宿主测试、Godot 内容提取、两组场景 smoke、Windows 导出及导出包 smoke。`-Graphical` 另捕获实际渲染截图。验证与运行每次从作者源提取，使用规范化内容指纹；纯图像变化单独记录表现摘要。内容或规则不兼容的旧档拒绝恢复。

场景 smoke 会临时修改内存中的场景，验证重命名、节点重排、保持全局变换的换父节点、移动商店及道路、重复身份、删除引用和不支持的变换，并在结束后恢复原几何。它不保存这些变更到场景文件。实际身体查询使用 Godot 物理空间；核心使用同一提取几何规划路径。

## 代码与记录

| 模块 | 职责 |
| --- | --- |
| `src/CozyTown.Core/Town` | 内容校验、局部观察、独立规则、世界提交、资产不变量和逻辑快照 |
| `src/CozyTown.Model` | DeepSeek 传输、严格回复解析、共用预算与恢复去重 |
| `game/Host` | 场景提取、主线程派发与结果受理、真实碰撞、玩家输入、原子存档和日志 |
| `game/World`、`game/Art` | 地图、身体、动画和界面表现；[素材来源](art/SOURCES.md) |

每个运行目录包含内容与初态、版本清单、连续 JSONL、模型安全字段及验证或结束快照。导出持有日志写锁，复制一个完整前缀并记录条数及字节数。记录中断会停止世界提交和新派发。恢复创建新分支并保留来源位置；来源日志缺失时可以继续合法世界，但会明确记录旧前缀不可用于回放。

记录包含完整输入与结果，回放逐边界重算并在首个分歧或缺依赖时停止。单元测试、自动场景 smoke、真实服务结果和用户画面反馈分别报告。
