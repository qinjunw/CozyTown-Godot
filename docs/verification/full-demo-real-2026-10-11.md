## 拒绝、资源与续接

基准产生 `unexpected_action_fields` 3 次、`insufficient_assets` 1 次、`participant_busy` 2 次规则拒绝。对照产生字段拒绝 5 次、资产拒绝 3 次。邀请使旧待办退休、会话结束、旧世界会话拒绝与规则拒绝分别记录；这些事件可能关联同一逻辑请求，不能相加为额外 HTTP 失败。

[12 条字段及资产拒绝明细](evidence/full-demo-real/rejected-samples.json)保留候选、冻结自有库存与金币、当时 offer，以及按交付记录重建的判定时资产。8 条字段拒绝均包含动作不允许的字段，常见为在 `respond/propose_exchange` 中填写 `placeId`；其中一条 `respond` 同时填写物品、数量与价格。4 条资产拒绝在冻结输入时就已超出自有库存：基准 Eli 卖 3 份谷物但仅有 1 份；对照 Mina 在零库存时卖 2 份浆果、1 份汤或 1 份浆果。判定时资产仍与冻结资产一致，这四例没有发现请求冻结后的库存变化。

上述样本证明字段与资产约束未被模型遵守。提示词如何改写需要后续修复验证，不能据此宣布改写会提高真实采用率。世界拒绝保持有效，没有将非法候选改写为成功。

基准、对照分别形成 8 次、4 次资源交付；从各居民初始资产沿活跃交付逐条重建，逐人金币与每种库存均与结束快照一致。重复逻辑执行、重复交付、重复玩家显示经历、居民重复经历及错误玩家会话显示均为零。完整核心和场景回放另行核对每个状态边界；快照中的总量字段没有作为独立资产证明。

两组各发生一次标记为恢复的真实派发，保留原逻辑 ID、冻结请求与阶段。原尝试均在 HTTP 前因 `host_request_retired_before_send` 取消，结算 0；恢复成为该逻辑请求唯一的 HTTP 尝试。旧世界会话结果被隔离。故每组 36 个 NPC HTTP 尝试对应 36 个可解析逻辑请求，不能再从分母扣掉一次恢复。
