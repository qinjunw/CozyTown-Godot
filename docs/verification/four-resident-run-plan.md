# 四人场景真实调用计划

本计划在垂直切片第一次真实场景调用前登记。执行分支为 `codex/four-resident-slice`；每次运行记录程序集版本、内容指纹、输入摘要、初态、模型协议及全部请求与结果。实测报告另行记录实际提交与结果。

## 输入与预算

- 沿用 `cozytown-godot-first-slice-20260920-v1` 的现有持久账本。接口探针已用 4 次、保守扣减 2,212 microCNY；本票剩余 44 次和 4,997,788 microCNY。
- 基准和资源对照各最多 22 次发送，正常发送及恢复补发共同计数；人民币 5 元和 48 次的总限制先到先停。
- 配置使用仓库外凭据及忽略目录内的现有账本；运行命令指向本机配置文件，记录不包含凭据、账户余额或机器凭据路径。
- 服务为 DeepSeek `deepseek-flash`，关闭思考，JSON 对象输出，最多 512 输出 token；其余限制沿用[接入合同](../REAL_MODEL_CONTRACT.md)。运行协议见 `TownModelProtocol.Version`。

## 执行前条件

1. 核心、模型和宿主离线测试通过，Windows 导出通过场景 smoke。
2. 基准与对照均加载同一 Godot 场景、居民日程、人格、规则和协议。仅 `Content/counterfactual.json` 改变初始资源分配，总资源保持相同。
3. 同场四人从住宅走向各自日程地点，通过普通决策入口获得行动机会；驱动不指定社交对象、接受结果或候选。
4. 实际场景检查人物、碰撞、观察和存档可操作后才开始付费运行。

## 两组运行

先运行基准，再运行资源对照。每组使用普通世界时速（每现实秒 0.5 世界分钟），达到 180 现实秒或该阶段 22 次尝试后停止新增请求，等待已开始的调用结束或进入明确失败状态。未发送的决定不通过额外运行补足；预算不重置，也不自动重跑失败组。

每名居民至少一条被世界实际采用的 `real_model` 候选才计为该居民的真实路径证据。合法等待、拒绝和结束也是选择；仅服务成功、规则执行或规则回退不能计入。记录每条候选的冻结观察、世界校验及最终行为，保留失败、过期、拒绝和未采用样本。比较两组的对象、行动和交付结果，允许真实模型给出相同选择。

资源守恒和重复交付防护用固定测试覆盖；真实运行中是否发生交易按实际结果报告。暂停、坏档、恢复补发竞争及记录失败采用固定输入测试，不额外消耗真实预算。

## 输出与停止

每组输出完整 JSONL、初态与内容、结束快照、请求/响应安全字段、费用和发送数、每名居民的采用记录，以及通过项和未通过项。未知费用继续占用预留，未知远端终止继续占用并发槽；超时不视为服务停止。日志中断停止世界提交和派发。任何未达验收项均保留为未通过，不以重跑筛选成功样本。
