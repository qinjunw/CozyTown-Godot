## 完整逻辑快照

快照来自一个世界提交边界，包含该边界之前已受理的输入和结果，记录之后尚未消费的逻辑待办。多个居民、资产和空间状态不能分别在不同时刻采集后拼成一份存档。保存捕获与后续写盘分开；写盘期间世界可以沿原状态继续。

捕获本身不推进时间或身体、不消费事件、不派发请求。快照包含已接受但尚未消耗的世界推进量；新宿主丢弃旧帧中未封存的现实 delta，并重新建立采样起点，避免恢复首帧额外跳时。

| 状态组 | 一旦实现就必须保存的内容 |
| --- | --- |
| 身份与版本 | 快照身份、父运行/分支与记录位置、初态指纹、实验预算身份、结构版本、内容/规则/数值与物理配置标识；源构建版本供追踪 |
| 世界时间 | 世界时刻、未消费推进量、边界/结算游标、影响下一次推进的累积量与暂停语义 |
| 玩家与经济 | 位置、方向、空间、钱包、背包、已实现生产状态与结算游标、商店库存、已提交资源操作的去重依据 |
| 每名居民 | 固定身份、当前位置/空间、朝向、已选路线及路点/路段游标、进度、目标、阻塞与重试状态、日程进度、当前活动及阶段 |
| 共同活动 | 会面承诺、参与者、时间窗口、双方到场状态、会话轮次与发言权、已受理文本、交付状态及操作身份 |
| 观察与经历 | 当前待办实际使用的观察内容与时刻、经历及来源、影响决策的个人记忆和待处理事件 |
| 决策待办 | 原逻辑请求身份、居民与活动修订、原输入/模型配置、已接收但未处理的结果或错误、封存邮箱边界、排队顺序与调度游标、执行阶段、剩余等待与重试额度、已终结/去重记录 |
| 可复现状态 | 随机算法版本及当前状态、稳定排序规则版本、输入/事件序号、运行模式和记录检查点 |

快照使用显式版本的普通 C# 数据及 JSON 编码，要求必要字段存在且类型/范围合法。身体、承诺、会话、资产与待办交叉引用必须在隔离候选状态中验证。不能用缺省零值、出生点、初态钱包或重新邀约修补缺失字段。

尚未实现的生产链不提前构造空状态；每次加入影响后续行为的状态时，同时扩展快照、版本和续接验收。已发出请求使用的观察与上下文必须冻结，不能在读取后换成新的观察重新解释原请求。

节点、NodePath、RID、引擎运行实例号、Task、HTTP 连接、取消令牌与信号订阅不保存。宿主按稳定业务身份重新创建绑定；每个启用居民必须唯一绑定身体，节点遍历顺序不能决定恢复对应关系。渲染插值等纯表现状态可重建，不得触发游戏操作。

## 兼容性与文件发布

存档结构版本、影响模拟的内容指纹、规则版本、数值与空间查询配置须通过显式兼容检查。首版对未知结构或不匹配的模拟合同拒绝读取；不自动迁移、就近吸附、重新规划或清空活动。内容身份仍存在不能证明旧路线有效。

贴图、音效、字体和纯 UI 修改单独记录表现版本，不进入模拟兼容指纹。改变碰撞、身体尺寸、地点、规则或影响模拟的参数仍属于模拟变动。构建提交记录来源，不以提交不同这一条件单独拒绝存档。实验的精确场景回放另校验引擎与空间实现版本。

每次保存写入同目录临时文件，写入完成后重新解析并校验，再发布为用户选择的存档；替换已有档时保留上一份可恢复副本。失败不得把截断文件报告成成功，不自动覆盖唯一好档。恢复备份是明确动作，不能静默回退时间。文件替换和崩溃后选择有效档的行为必须在 Windows 故障注入中验证；序列化通过不等于断电持久性证明。

实验记录与现实调用账本独立于可回退世界快照。快照保存它们的关联身份与保存点序号，不通过加载旧档覆盖、截断或退还已发生的费用。首版保存完整运行记录；若记录缺失，世界续接与记录回放分别报告能力，不能把不完整记录标为可回放成功。

文件按生命周期分为快照 JSON、运行清单与追加 JSONL 事件记录、独立持久预算账本。快照封套保存版本与检查点，载荷保存世界及居民状态；清单关联起点快照、内容依赖和各记录文件。首版无需把所有数据写成一个可回滚文件；预算账本的事务存储实现须在切片中通过并发占用与进程重启用例，不能用无保护的 JSONL 追加代替原子预算更新。

## 恢复事务

1. 在提交边界添加临时读档暂停原因，冻结游戏写入；I/O 可接收结果并追加现实用量。旧世界、会话代数、请求与订阅保留到预检通过。
2. 在隔离候选对象中解析、检查版本、内容、全量字段与引用，并验证保存的路线游标、活动、资产及身体可行性。场景准备与空间同步不得先修改旧世界的权威状态。
3. 任一预检失败，丢弃候选，移除本次读档暂停原因，报告具体字段/身份；其他暂停原因不变。旧待办与响应队列仍按旧世界的规则处理。
4. 全部预检通过后，在一个受控切换点退役旧会话、建立新会话代数、提交候选世界并重绑场景。取消旧传输只是尽力清理；旧会话结果即使仍到达也只能进入拒绝记录和用量账本。
5. 发布同一版本的身体、活动、观察与界面，恢复原逻辑待办。完整发布成功后才移除本次读档暂停原因，并在其他暂停原因均已解除时开放推进和真实请求派发。若提交后的显示/绑定失败，保持新逻辑世界并停在可诊断恢复状态，禁止推进、派发和生成新的完整快照；允许重建同一已提交状态的显示，或重新进行一次合法读档。不得假称回滚成功或再次执行资源操作来重试画面。

读取同一快照再次继续产生新运行分支，保存来源快照、父分支和分叉序号；保留快照中的业务身份。分叉后的新事件/活动标识带分支范围，不能与另一分支新增事件相撞。加载不能导入保存点之后才发生的经历或响应。

## 逻辑待办与真实传输

| 身份 | 生命周期与用途 |
| --- | --- |
| 运行/分支身份 | 关联初态、来源快照和记录；读档继续产生分支，已存在的业务身份保持 |
| 会话代数 | 每次活跃世界实例新建，用于隔离退役宿主与晚到回调；不沿用存档中的运行时代数 |
| 逻辑请求身份 | 对应原人物在原活动中尚待完成的一次决定；保存恢复后保持，并校验上下文修订与有效窗口 |
| 传输尝试身份 | 每次外部发送新建；对应一次真实等待与可能收费，不因逻辑请求相同而合并费用 |

响应先进入邮箱，再在世界提交边界检查运行分支、会话代数、逻辑请求、尝试、居民/活动修订、有效窗口和终结记录。重复或失效响应只能被拒绝；不能再次发言、扣款或交付。

候选结果已经包含在快照中时，沿原阶段继续验证和提交，不重新调用模型。通过快照完整性与待办关联校验后，将这份封存结果绑定到新会话，记录原尝试和恢复来源；这一步不适用于读取后才到达的旧网络回调。尚无结果的请求保留原观察、输入、会话轮次和逻辑身份，按自动续接策略恢复。若日程边界或上下文已经使请求失效，先按规则终结，不为失效请求付费。

自动续接：同一逻辑请求在同一实验预算范围内至多追加一次恢复尝试，发送前在账本中原子、持久地占用该恢复名额与所需预算并登记尝试。此限额按实验预算身份和原逻辑请求身份核对，跨读档分支和进程共同使用；再次读取同一旧档不能刷新额度。发送后崩溃或结果未知时保留占用，不能领取第二次恢复尝试。普通重试与恢复补发共享总预算，不能分别计算后突破上限。补发后仍失败或额度耗尽时执行合法规则回退并标明来源。

外部账本记录已确认费用与尚未结算的请求占用，未知费用不按零计。退役会话或请求取消不能自行释放仍未确认结束的物理请求占槽。登记失败不得发请求；缺少可核对账本或预算信息时暂停真实调用并报告原因，规则回退不伪装为模型成功。新的预算须由明确的实验配置建立，不能因读取或复制存档隐式重置。具体额度、超时、计费估算和提供方能力由[模型接入票据](https://github.com/qinjunw/CozyTown-Godot/issues/11)确定。

等待与截止分用以下时钟，暂停期间结果和超时只能入邮箱，不能改写世界。

2026-10-10 玩家对话决策增加窄范围例外：仅有对话面板暂停时，允许当前有效玩家会话生成和展示文本；世界与 NPC 仍暂停，经历留待正常提交边界。菜单、失焦、读档或故障叠加时继续禁止派发与展示。面板会话、已显示文本与待提交经历进入快照和记录，关闭/切人及恢复规则见[玩家模型对话合同](PLAYER_DIALOGUE_CONTRACT.md)。

| 时限 | 暂停和恢复规则 |
| --- | --- |
| 世界日程与活动截止 | 使用世界时间；菜单、失焦、读档及应用关闭期间不推进 |
| 决策待办的剩余等待额度 | 在活跃宿主中等待未完成结果时按现实单调时间递减，菜单与失焦期间仍递减；及时收齐结果或到期后停止该段计时；保存相对余量，应用关闭期间不扣减 |
| 一次真实传输超时 | 使用本次尝试的现实单调时间，菜单与失焦不冻结；恢复补发重建计时器，上限取逻辑余量与服务单次超时的较小值 |

记录完整响应到达的相对时刻及邮箱序号，以其是否早于传输期限判超时，不能仅因解除暂停时已过期限而丢弃及时收到的回复。到达恰在期限视为超时；超时或失败候选亦须封存和恢复。快照捕获时剩余等待已为零的待办不能借读档补发复活。新尝试的额外等待和消耗如实记录，不能宣称与未中断的真实模型运行结果相同。

活动窗口采用半开区间，结束时刻先处理日程切换和到期，再受理候选；恰在截止时刻到达或返回也不能恢复已失效互动。世界推进按跨越的活动与日程边界切分，各处理阶段内部按宿主记录的输入序号处理，不由信号订阅或线程调度顺序隐式决定。读档暂停原因仅属于本次宿主操作；菜单与失焦由当前界面/焦点重新计算，不照搬旧进程的失焦状态。

## 记录与回放

运行包包含版本化清单、初态快照、追加输入/结果记录与调用用量关联。清单必须能定位所用内容清单及确切版本资产；核心回放随包保留独立内容数据，场景回放另需对应引擎/场景包，单独哈希不能重建缺失内容。记录每个边界的序号、世界时刻、接受的时间预算/命令、暂停变化、决定来源、完整模型输入与响应/错误、接收及受理边界、随机状态检查点、空间查询输入及结果、关键状态摘要。提供者密钥与授权头不进入存档或导出记录。

运行包还保存起点的预算/在途请求视图，以及后续实际接受的现实时间输入、额度判定、名额占用和释放事件。回放用这些输入维护隔离的模拟账本，重现预算等待、恢复准入与并发限制；不能查询当前真实账本代替当时事实。

“已收到”“已受理”“已拒绝”和“已执行”分别记录。日志具有结构化字段，不仅是自由文本台词；缺少输入序号或记录中断时标明可回放的最后完整前缀，不跳过缺口继续报告通过。

保存成功还要求其关联的记录前缀已落盘，且快照中的检查点与记录一致。运行记录写入失败时停止新的实验推进和真实请求，保留最后确认的前缀并报告中断；不能以静默丢日志维持“可回放运行”的标记。

| 模式 | 输入与验证 | 通过的含义 |
| --- | --- | --- |
| 固定替身 | 固定输入与可控响应，经正常居民/世界入口运行 | 验证规则与故障边界，不证明真实模型行为 |
| 核心记录回放 | 用记录中的时间、命令、响应与空间事实重跑规则；校验每次查询输入及规范化状态 | 相同逻辑过程可复现，不证明 Godot 再次计算了碰撞 |
| Godot 场景回放 | 同一引擎及空间配置重新执行查询，比较身体、空间结果与核心状态 | 验证记录场景在指定配置下的重现，不承诺跨版本物理逐位一致 |
| 真实模型运行 | 实际传输、拒绝、失败、回退与用量单独标识 | 证据来自全部实际样本，不以固定替身或回退冒充 |

回放隔离于活跃游戏，不请求真实模型，不写真实调用预算；记录中的计时到期也作为输入，不能依赖当前网络或回放耗时。身份映射按业务关系与记录中的创建顺序建立，不能忽略请求/活动 ID 后只比较最终资产。

第一次分歧即停止，报告边界序号、实体/字段、预期与实际、相关输入和版本。身份、资产、阶段、去重与逻辑待办精确比较；位置按版本化数值合同的容差比较，首切片固定该合同。完整回放执行器后续交付；首切片先交付满足这些字段的记录导出。

## 公开验证入口与验收（待实现）

核心提供可直接测试的捕获快照、预检恢复、切换候选状态、推进输入与比较检查点入口；Godot 提供 headless 场景验证入口及 Windows 操作入口。故障输入通过这些入口控制文件失败、传输完成顺序与空间事实；不直接改资产或活动来伪造结果。

| 用例 | 通过判据 |
| --- | --- |
| 连续捕获快照但不推进世界 | 时间、身体、事件和请求数不因捕获变化；恢复首帧不消费旧宿主未封存 delta |
| 四人同时有行程/互动，任意提交边界保存 | 所有状态同一修订，恢复每人身份、活动与位置，无丢人或错绑 |
| 赴约途中保存，随后继续 | 保持原路线与游标、承诺和阻塞状态；不从出生点/目的地重新计划 |
| 等待回应、交谈中、交付前后保存 | 继续原会话轮次与逻辑请求，资产操作最多执行一次 |
| 读档失败：截断、字段缺失、未知版本、悬空引用、坏路线 | 当前世界及旧待办保持可继续；不得先退役再发现失败 |
| 内容/规则不兼容；仅修改贴图 | 前者拒绝并定位差异；后者在模拟指纹不变时允许读取 |
| 新世界切换后旧回调、重复响应同时到达 | 旧响应拒绝，重复结果不执行，实际用量仍保留 |
| 重复读同一等待模型的快照 | 不刷新重试与费用额度，不导入未来经历；按选择的恢复策略继续 |
| 两个进程使用同预算恢复同一待办；占额/发送后终止进程再启动 | 至多领取一次恢复尝试，重启不清除已占额度，未知用量不按零处理 |
| 已封存的模型候选与读取后到达的旧回调 | 前者继续原待办且不重发，后者拒绝；不能统一丢弃或统一改代数 |
| 菜单与失焦暂停叠加，期间响应/超时到达 | 解除一个原因仍暂停；所有游戏提交等恢复后检查 |
| 暂停时先收齐有效回复，随后传输期限经过 | 用记录的到达时刻判定，恢复后继续世界合法性检查；不被后续超时覆盖 |
| 到场、候选响应与日程截止同一时刻 | 截止和日程优先，过期互动不再交付或占用下一项日程 |
| 写盘/替换失败或进程在发布阶段中断 | 原好档/备份可识别，坏文件不被报告为保存成功 |
| 新世界已提交后故意令显示发布失败 | 进入暂停故障状态，重建显示不重做交易，不宣称旧世界未变 |
| 保存点之后运行出新经历再读旧档 | 世界回到保存点已有经历，现实消耗累计值不减少 |
| 修改回放中的一个输入、响应、顺序或空间结果 | 在首个分歧停止并定位，不能继续覆盖原记录 |
| 删除运行记录中段或所需版本内容 | 明确缺口或缺依赖，拒绝宣称完整回放通过 |

## 参考证据的边界

Unity 固定提交的[完整快照矩阵](https://github.com/qinjunw/CozyTown/blob/68a1dde7c7099f3e9ee7e975141d0bf9d18099aa/Assets/CozyTown/Tests/PlayMode/CompleteWorldSnapshotMatrixPlayModeTests.cs)与[存储故障测试](https://github.com/qinjunw/CozyTown/blob/68a1dde7c7099f3e9ee7e975141d0bf9d18099aa/Assets/CozyTown/Tests/EditMode/Save/JsonFileSaveStorageTests.cs)提供无副作用捕获、途中续接、预检失败、文件失败及提交后故障的参考用例。它们在本轮仅作源码与归档证据核验，未重新运行，也不算 Godot 验收。

旧项目的[验证范围](https://github.com/qinjunw/CozyTown/blob/68a1dde7c7099f3e9ee7e975141d0bf9d18099aa/docs/verification/complete-agent-snapshots-2026-09-19.md)未交付完整轨迹回放；[待办快照测试](https://github.com/qinjunw/CozyTown/blob/68a1dde7c7099f3e9ee7e975141d0bf9d18099aa/Assets/CozyTown/Tests/EditMode/NpcAgents/NpcDecisionSnapshotTests.cs)中的请求计数与占槽恢复也不能证明跨进程费用账本或提供方幂等。新项目另行验证这些合同，不复制 Unity 旧档迁移分支或预设人物配对。
